### Entry 023
- Date: 2026-09-24
- Decision: **A review finding that cannot be resolved to a line in the diff is dropped, not
  reported.** Model output is anchored against the parsed diff: an exact line, or a re-anchor
  to the nearest visible line within 6 rows which is *marked* as re-anchored, or a drop with a
  recorded reason that the report counts. Rationale: REV-007 asks that a reviewer can navigate
  directly to the code, and a plausible-looking line number that points nowhere costs a
  reviewer the same attention as a real finding and returns nothing. Making it a property of
  the system rather than an instruction to the model is the only way it holds.
- Status: Active.

### Entry 024
- Date: 2026-09-24
- Decision: **Test adequacy and the security pass are deterministic first, with the model
  given that evidence rather than asked to reconstruct it.** Static findings carry
  `model=None`, and the report shows provenance per finding. Rationale: whether a change
  altered logic, and whether any test names the module, are facts; a reader can trust them at

### Entry 025
- Date: 2026-09-24
- Decision: **An incomplete review is not a clean review** - the TEST-009 rule applied to
  REV-*. A model error, unparseable output or a truncated diff sets `complete=False`, and
  `aica review` exits **6** for it, distinct from 2 (findings found) and 0 (clean). Rationale:
  a pre-merge gate that cannot tell "nothing wrong" from "the check did not run" is worse than
  no gate, because it converts a failure into an approval.
- Status: Active.

### Entry 026
- Date: 2026-09-24
- Decision: **Untracked files are reviewed by default, by synthesising an all-added diff from
  the file rather than staging it.** `git.diff` gained `include_untracked`. Rationale: a new
  module is what an agent most often produces and `git diff` cannot see one, so the review was
  silently skipping the largest part of an agent's work. `git add -N` would have made it
  visible, but writing to the index to answer a read-only question is exactly what GIT-010
  exists to prevent, so the diff is built from the file's contents instead.
- Status: Active.

### Entry 027
- Date: 2026-09-25
- Decision: **The approval queue holds records and never executes.** Approving a request
  does not replay the action; the client re-sends it and it passes every gate again. The HTTP
  API's default approver is now `QueueingApprover`, which parks the request and *still
  denies*, so an unattended refusal leaves something for a human to decide rather than a lost
  409. Rationale: a queue that ran actions on approval would be a second execution path with
  different guards from the first. Self-approval is refused only while RBAC is enabled,
  matching SEC-006, so a single-developer workspace is not locked out of its own queue.
- Status: Active. Follow-up: binding an approval to one specific re-execution.

### Entry 028
- Date: 2026-09-25
- Decision: **NFR-003 is defined as "one agent task per working tree, refused not queued".**
  The BRD asks for concurrency-aware behaviour without a rule. The hazard is two agents in one
  checkout seeing each other's half-edits, so an agent run takes a file lease (binding CLI
  and server alike) and a second run is refused with the holder named. Parallel work is
  supported through separate worktrees/clones, which are separate repositories with separate
  leases. Queueing was rejected because a queued plan would execute against a changed tree.
  Sessions get revisions (stale saves refused) and owners (enforced only with RBAC on).
- Status: Active.

## Known Limitations

- Semantic retrieval uses hashing embeddings, not a trained embedding model: it captures
  vocabulary overlap, not deep semantics.
- Non-Python chunking is heuristic (brace balancing), not tree-sitter. Malformed sources fall
  back to line windows.
- Execution is subprocess-isolated only (Entry 012). Since 2026-09-26 a timeout or cancel
  kills the whole process tree, and a step gets no more time than its run has left.
